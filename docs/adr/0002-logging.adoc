= ADR-0002. Логирование

Статус:: Принято
Дата:: 2026-11-06

== Контекст

Для отладки и сопровождения нужно читать логи бэкенда и искать запросы по `request_id`. Бюджет инфраструктуры — до 20 долларов в месяц (максимум 30), сервер один. Стек ELK (Kibana) и Graylog требуют 2–4 ГБ памяти только под логи. Данные пользователей чувствительные и должны оставаться в РФ.

== Решение

* Бэкенд пишет структурированные логи в формате JSON в стандартный вывод (stdout).
* Docker сохраняет логи на диск с ротацией: 7 файлов по 50 МБ (не более 350 МБ на контейнер); при заполнении удаляется самый старый файл.
* Для просмотра используется Dozzle — веб-интерфейс для логов Docker-контейнеров (поиск по тексту, просмотр в реальном времени), закрытый паролем. Разворачивается в том же `docker-compose`.
* Каждая строка лога содержит: время, уровень, `request_id`, метод, путь, HTTP-статус, время обработки, внутренний `id` пользователя (если известен), для ошибок — `code` и `reason`.
* В логи не пишутся: тексты записей, токены, почта, имя, тела запросов.

== Рассмотренные альтернативы

* ELK (Kibana) и Graylog — слишком тяжёлые для одного недорогого сервера.
* Облачные сервисы логов (Grafana Cloud, Sentry и подобные) — данные хранятся за рубежом.
* Grafana + Loki — подходит при росте: около 300–500 МБ памяти, поиск по полям, графики. Отложено до появления потребности.

== Последствия

* Нулевая стоимость и минимальная настройка.
* Нет сложных запросов и графиков; глубина хранения ограничена ротацией.
* При необходимости переход на Grafana + Loki не требует изменений в коде: формат логов остаётся тем же.
